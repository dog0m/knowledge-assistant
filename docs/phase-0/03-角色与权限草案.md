# 角色与权限草案

## 1. 设计原则

- 默认拒绝访问，按用户、部门、文档标签或知识库进行过滤。
- 检索权限必须在召回前生效，不能只在回答展示阶段过滤。
- Agent 工具按角色白名单启用，首版只允许只读工具。
- 所有文档访问、下载、问答引用和管理操作记录审计日志。

## 2. 角色矩阵

| 能力 | 普通用户 | 知识库维护员 | 部门管理员 | 系统管理员 | 审计人员 |
|---|---:|---:|---:|---:|---:|
| 查询已授权文档 | ✓ | ✓ | ✓ | ✓ | 按授权 |
| 上传文档 | - | ✓ | ✓ | ✓ | - |
| 更新/删除本人负责文档 | - | ✓ | ✓ | ✓ | - |
| 管理部门知识库 | - | - | ✓ | ✓ | - |
| 管理用户和角色 | - | - | - | ✓ | - |
| 查看系统运行日志 | - | 受限 | 受限 | ✓ | ✓ |
| 导出审计记录 | - | - | - | ✓ | ✓ |
| 使用只读结构化查询工具 | 按授权 | ✓ | ✓ | ✓ | - |
| 使用写入型 Agent 工具 | - | - | - | - | - |

## 3. 权限来源

| 事项 | 方案候选 | 当前选择 |
|---|---|---|
| 用户身份 | 本地账号 / LDAP / AD / SSO | 阶段 0 使用本地账号；生产接入前评估 LDAP/SSO |
| 部门信息 | 身份系统同步 / 手工维护 | 阶段 0 手工维护 `department` 字段 |
| 文档权限 | 目录继承 / 标签 / ACL 导入 | 使用文档标签 `department=platform` 和 `sensitivity=L0` |
| 离职与禁用 | 定时同步 / 管理员手工操作 | 阶段 0 由系统管理员手工禁用，目标生效时间 5 分钟内 |
| 审计保留 | 按公司制度确定 | 试点保留 30 天 |

## 4. 权限验收场景

1. 用户 A 可以检索部门 A 的文档，不能看到部门 B 的文档片段或引用。
2. 用户被禁用后，新的问答和下载请求立即或在约定同步周期内失败。
3. 文档权限变更后，旧索引不会继续向无权限用户召回。
4. 知识库维护员不能修改用户角色，也不能调用写入型工具。
5. 管理员和审计人员可以追溯一次回答使用的文档及权限判断结果。
